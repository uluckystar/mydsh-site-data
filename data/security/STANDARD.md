# MyDSH 安全报告标准(Security Report Standard)

> 版本:v1.0(2026-08-17)· 维护:mydsh.dev 社区
> 本文件定义"什么是安全报告、怎么做出来、怎么评判"。所有在 mydsh.dev 发布的正式安全报告均遵循本标准。

## 一、什么是安全报告

安全报告是对一个 DSH 插件的**代码级安全评估结论**,回答三个问题:

1. **这个插件安全吗?** —— 综合风险分 0-100,越低越安全
2. **它做了什么?** —— 行为分析(有没有执行命令、读敏感数据、外发数据)
3. **能不能用?** —— 结论分级:通过 / 存在风险 / 恶意(禁用)

安全报告**不是**"这个插件好不好用",只评估安全;报告由机器(AI 初评)+ 深度审查(Codex)产出,**不保证绝对正确**,但给出可核查的证据链。

## 二、评估维度(每份报告逐项检查)

| 维度 | 检查内容 | 危险信号 |
|---|---|---|
| 代码执行 | 是否执行 shell/命令/远程脚本 | `child_process`、`exec`、`eval`、`curl\|sh`、install/postinstall 脚本 |
| 数据外发 | 是否把数据发到第三方 | 非官方域名 fetch、隐藏回传、telemetry 到未知端点 |
| 敏感读取 | 是否读取用户凭据/私密文件 | `~/.ssh`、`~/.dsh/.credentials`、`~/.codex`、环境变量 token |
| 依赖风险 | 依赖是否异常 | 可疑来源、数量异常、混淆依赖 |
| 混淆/后门 | 是否隐藏恶意逻辑 | 混淆代码、base64 大段、反向 shell、挖矿 |
| 权限边界 | 是否越权操作 | 修改 profile 配置、静默写文件、禁用安全机制 |

## 三、评分标准(安全分 0-100,分数越高越安全)

> 报告展示的是**安全分** = 100 - 风险分。分数高 = 可以放心,分数低 = 风险高。

| 安全分 | 级别 | 含义 |
|---|---|---|
| 80-100 | 🟢 安全 | 未见明显风险,正常插件 |
| 50-79 | 🟡 需注意 | 存在可疑点需注意(如读 token 但仅用于官方 API) |
| 20-49 | 🟠 谨慎 | 有明显风险行为(执行远程代码/外发数据),建议谨慎 |
| 0-19 | 🔴 危险 | 确认木马/后门/挖矿/数据窃取 → **立即禁用** |

## 四、结论分级(给用户的明确建议)

| 结论 | 用户建议 | 处置 |
|---|---|---|
| ✅ 放心用(safe) | **可以直接安装使用** | 正常展示,报告可下载 |
| ⚠️ 谨慎用(cautious) | **可以用,但注意风险点**——报告里写明"哪部分要小心" | 展示报告+风险分+注意点 |
| 🚫 不要用(block) | **不要安装**——有明确恶意证据 | **立即禁用**:插件市场拒绝安装,列表显示🚫 |

> 原则:**每个插件必须给出"用还是不用"的明确答复**,不允许模糊的"中危/高危"标签代替结论。
> 风险分(0-100)作为参考数值保留,但**用户建议是最终决策依据**。

## 五、评估流程(两级)

```
第一步 AI 初评(gpt-5.6-luna,自动)
  拉仓库元数据+目录树+关键文件 → 判断是否 DSH 插件 + 初评风险分 + 可疑点
  → 写 submissions.json(留痕,含提交人/时间/IP 哈希)

第二步 深度审查(Codex gpt-5.6-sol,自动)
  只对"已通过插件市场校验的插件"执行
  拉完整代码 → 按本标准的六个维度逐项分析 → 出正式报告
  → 报告必须包含:评估分支(branch)、该分支最后更新时间(updated_at)
  → 写 reports.json(发布)+ blocked.json(恶意禁用)

人工复核(可选)
  高风险/存疑报告可被维护者人工复核后更新
```

## 六、报告字段

```json
{
  "full_name": "owner/repo",
  "risk_score": 0-100,   // 风险分(展示时用 100-风险分 = 安全分),
  "verdict": "通过|存在风险|恶意",
  "user_advice": "放心用|谨慎用|不要用",
  "branch": "main",                // 评估的分支
  "updated_at": "2026-08-17T...",  // 该分支最后更新时间(评估对象版本)
  "summary": "一句话结论",
  "details": ["维度1分析", "维度2分析", "..."],
  "action": "release|review|block",
  "reviewed_at": "ISO 时间",
  "initial_score": "AI 初评分数"
}
```

> **branch 和 updated_at 是必填项**:安全报告必须明确"评估的是哪个版本的代码"——
> 插件更新后旧报告失效,用户可通过更新时间判断报告是否过期。

## 七、可信度说明(如实告知)

- 报告由 AI 自动生成,基于公开代码分析,**不保证发现所有恶意行为**
- 建议:重要插件安装前查看报告;发现可疑行为欢迎提交复核
- 恶意判定 = 明确证据(后门/窃取/挖矿),不是"可疑就禁"
- 每份报告可下载(JSON),证据链(源码位置)随报告公开
