# MyDSH 插件安全报告标准 v1.1

> MyDSH 是 DeepSeek Harness 生态的非官方社区。本标准用于公开代码的静态安全评估，不代表 DeepSeek 官方结论。

## 一、用户需要看到什么

每份报告必须直接回答：

1. 这个仓库是否属于 DeepSeek Harness 生态；
2. **安全分是多少**；
3. 用户应当放心用、谨慎用，还是不要用；
4. 报告评估的是哪个分支、哪个版本；
5. 结论对应哪些代码证据。

公开页面、接口、下载报告、通知和自动化结果统一使用 **安全分 0-100，分数越高越安全**。不得再公开另一套方向相反的总分。

## 二、六个检查维度

1. 代码执行：`exec`、`spawn`、`eval`、远程下载执行、生命周期脚本；
2. 数据外发：第三方域名、遥测、用户内容上传；
3. 敏感读取：环境变量、令牌、SSH、DSH/Codex 配置、用户文件；
4. 依赖安全：依赖来源、版本锁定、安装脚本、供应链边界；
5. 混淆与后门：隐藏载荷、挖矿、代理跳板、持久化；
6. 权限边界：文件系统、Shell、网络、宿主能力是否符合最小权限原则。

功能所需且明确告知的模型调用、图片上传或网络请求，不能单独作为恶意证据。必须区分正常功能权限、设计风险和隐藏恶意行为。

## 三、安全分

| 安全分 | 展示说明 | 含义 |
|---|---|---|
| 80-100 | 安全性较高 | 未见明显危险模式，仍需关注报告中的使用边界 |
| 50-79 | 需要注意 | 存在权限、数据处理或供应链风险 |
| 20-49 | 建议谨慎 | 存在显著风险，不建议在敏感环境中直接使用 |
| 0-19 | 高风险 | 发现严重漏洞或高度危险行为 |

安全分是综合参考值，不能替代代码证据和明确的用户建议。

## 四、结论与处置

| 结论 | 用户建议 | 处置 |
|---|---|---|
| 通过 | 放心用 | 正常展示并提供完整报告 |
| 存在风险 | 谨慎用 | 展示风险边界、证据和缓解建议 |
| 恶意 | 不要用 | 只有明确木马、后门、秘密数据窃取或挖矿证据时才禁用 |

三组字段必须严格一致：

- `通过` + `放心用` + `release`
- `存在风险` + `谨慎用` + `review`
- `恶意` + `不要用` + `block`

严重漏洞但没有恶意证据时，应给出“谨慎用”和修复建议，不得标记为恶意或加入禁用列表。

## 五、评估流程

```text
AI 初评
  读取仓库元数据、目录树和关键文件
  输出安全分、可疑点和是否需要深度复核

深度复核
  只读检查完整代码和六个安全维度
  确认分支与该分支最后提交时间
  输出完整 Markdown 报告和结构化结论

发布
  校验字段、分数方向、结论一致性和报告完整性
  写入权威数据仓库
```

## 六、正式报告字段

```json
{
  "full_name": "owner/repo",
  "safety_score": 0,
  "score_type": "safety",
  "verdict": "通过|存在风险|恶意",
  "user_advice": "放心用|谨慎用|不要用",
  "branch": "main",
  "updated_at": "2026-08-21T00:00:00Z",
  "summary": "一句话结论",
  "details": ["带代码证据的检查结果"],
  "action": "release|review|block",
  "review_status": "complete|pending",
  "reviewed_at": "ISO 8601 时间",
  "initial_safety_score": 0,
  "report_md": "完整 Markdown 报告",
  "standard": "MyDSH-Security-Standard-v1.1"
}
```

正式报告必须包含 `branch`、`updated_at` 和 `report_md`。资料不完整或模型输出异常时只能标记为 `pending`，不能伪装成正式结论。

## 七、可信度说明

- 报告由 AI 基于公开代码自动生成，不保证发现所有问题；
- 插件更新后，旧报告可能失效；
- 用户应结合报告版本、代码证据、实际权限和自身环境判断；
- 对误报、漏报或版本变化，社区应重新复核并更新报告。
